# Session 3 homework: AES-GCM comment storage

Session 03, slide 30, assigns AES-GCM encryption of the NotesApp `comment`
column. The Caesar and image exercises are classroom activities and are not
included in this homework submission.

## Run

Follow the [root startup instructions](README.md#requirements-and-startup),
including generation of both independent keys required by this combined
Session 3/Class 4 application. No workstation-specific virtual environment or
editor settings are required.

## Implementation

- `web/comment_crypto.py` uses AES-256-GCM from `cryptography`: a new random
  12-byte nonce for every write, a 16-byte authentication tag, and UTF-8 comments.
- The stored TEXT format is `aesgcm:v1:` followed by Base64 encoding of
  `nonce || ciphertext || tag`. Base64 is serialization, not encryption.
- AAD binds ciphertext to `notesapp:notes:<id>:comment:v1`; moving ciphertext to
  a different note fails authentication.
- `web/app.py` encrypts comment writes and authenticates/decrypts reads for the
  student page, teacher page, note API and CSV export.
- `web/migrate_comments.py` migrates legacy plaintext in one transaction at web
  startup. Existing ciphertext is authenticated and left unchanged; NULL is
  preserved; corruption or the wrong key aborts and rolls back migration.

The secret is generated by `scripts/generate_comment_key.py`, saved separately
from PostgreSQL in `.secrets/comment_key.b64`, ignored by Git, and mounted as
`/run/secrets/comment_encryption_key`. Generation preserves an existing valid
key. Keep it to decrypt records after a restart; replacing it is not rotation.

## Verification

```sh
docker compose exec -T -e NOTESAPP_TEST_DB=1 web python -m unittest discover -s tests -p 'test*comment*.py' -v
docker compose exec -T web python migrate_comments.py --dry-run
docker compose exec -T db psql -U notesapp -d notesapp -c "SELECT id, left(comment, 40) FROM notes ORDER BY id LIMIT 3;"
```

The Session 3 tests cover 18 checks: Unicode/empty/NULL comments, fresh nonces,
key reload, wrong keys, nonce/ciphertext/tag tampering, cross-record moves,
authenticated reads on every application path, and atomic/idempotent migration.
Integration checks create and drop only disposable test schemas.

The seed dataset contains 60 notes. The migration leaves 60 authenticated
encrypted comments and no plaintext comments. Student/teacher pages still show
readable text. Earlier before/after verification of the recovered records gave
the same SHA-256 digest; local snapshots and student data are not uploaded.
`scripts/verify_comments.py` provides optional `--capture` / `--expected` modes
for repeating such a comparison on a deployment's own data.

Encryption protects stored comments; it does not enforce ownership, escape HTML,
secure transport, or repair other deliberately planted teaching flaws.
